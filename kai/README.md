# 普段の回のキット（3麻・4麻・会ごと）

普段の回は、トップページ（`kai/`。参加者向け。日時と場所・組み合わせ・当日の流れ・打ち上げ）と点数入力ページ（`kai/score/`）を使う。幹部用ページ（`kai/kanbu/`）と、くじの会はくじのページ（`kai/kuji/`）もある。
切り替えボタンは「トップ・点数入力・ルール・早見表・対戦表」（ルール・早見表・対戦表は、その会にあるときだけ。対戦表はくじのページ。幹部用ページは「幹部用」も）。呼び名は 2026-11-01 に「参加者ページ・点数・点数表・くじ」から改め、2026-11-03 に「トップページ・点数早見表」を「トップ・早見表」に縮めた（1段に収めるため。主催）。
Halu杯の記念大会（店の貸し切り・ゲストあり）の部品は halu-cup リポ（第20回の一式）にある。

## 画面（2026-11-03 に使い勝手を見直した）

- 切り替えボタンは、参加者のページなら1段に収まる（幅360px以上の画面）。幹部用は6つなので2段になる。
- 大会の名前・色・切り替えボタンは、前に読んだ大会設定を端末に覚えておき、開いた瞬間に出す（localStorage の `halukai:shell:<会>`。6ページとも同じキーで、ルール・早見表は会のフォルダ名から会を決める）。組み合わせと点数は覚えず、毎回新しく読む（2026-11-03。切り替えた直後に、見出しとボタン2つだけの画面が約1秒出ていたため）。回の名前（`kai`）と開催日（`date`）も覚え、前に結果を見た回（下の `halukai:end:<会>`）なら、ルールと早見表のボタンは開いた瞬間から出さない。トップと点数入力は、開催日から後で結果が出たかをまだ確かめていない間も出さない（2026-11-14 主催「下のページが一瞬表示される」）。
- 大会設定と組み合わせは同時に読む。点数入力は、前に読んだ設定がくじの会で抽せんの日が過ぎていなければ、くじの型も一緒に読む。対戦表は3つとも同時に読む。
- 「↑」は、画面の半分より下へ動かしたときだけ出す。
- トップページの一番下に、このページのアドレスの QR コードを出す（2026-11-14。主催）。アドレスは配る形（Halu杯は `?g=` なし・ほかの会は `?g=<会>`）で、`index.html`・`#`・ほかの `?` の後ろは付けない。`openExternalBrowser=1` も付けない（LINE の QR 読み取りでは LINE の中のブラウザで開くが、それでよい。2026-11-14 主催）。QR はページの中で作る（外のライブラリは使わない。8ビットバイト・誤り訂正 M・型番1〜6＝106バイトまで。入らなければ出さない）。読み込みが終わるまでは、下の切り替えボタンと同じく出さない。結果が出たら出さない（下の「結果」）。
- 抜け番が1つもない回は、抜け番の表・列・説明を出さない（2026-11-07 主催「抜け番はなくなったので項目を消して」）。見るのは組み合わせ表と型で、どちらもまだなければ人数が卓で割り切れるか（トップは組み合わせ表と人数だけ）。欠席などで抜け番ができると、また出る。
- 入力欄の枠は `--field`（#8c8c86。白地で3.4:1）。カードと表の線は `--line` のまま。
- トップ: 名前を選ぶと、一番上に「次は〇半荘目・〇卓」を出す。受け口の入力済みの卓から決める（抜け番・お休みなら、その次に打つ卓も）。
  - 自分の席の表は、点数が入った半荘を薄く、次の半荘に色をつける。席と決勝の決まりは、表のすぐ下に1文ずつ置く。
  - 結果（2026-11-14 主催）: 決勝の最後の半荘の決勝の卓がぜんぶ入ったら、一番上に「結果」の欄を出す（優勝を大きく・決勝の2位から下・自分の順位・最終順位の表）。「次は」・決勝ライン・当日の流れ・日時と場所・一番下の QR コードは出さない。自分の卓の欄は名前を選ぶ所だけにして、一番上（結果の上）へ回す（見出し・自分の表・最新に更新・席の決まりは出さない）。切り替えボタンのルールと早見表も、トップ・点数入力・対戦表・幹部用のページで出さない（どのページも同じボタンにする。幹部用ページには自分の「幹部用」が残る。ルール・早見表のページそのものは変えない）。点数入力ページの「点数の報告（卓ごと）」の欄も、結果が出て全部の卓の点数がそろったら出さない（上の1文は「結果が出ました」。入力中は消さない。直すときは `score/?unei=1` で開くと出る）。最終順位の計算は点数入力ページの `finalRanking` と同じ（順位決定戦の行には、その卓で決める順位の幅を添える）。全部の半荘が確定したら「結果（確定）」。最終順位の後ろに、トータルの順位（決勝2半荘目から後を除く＝全員が打った予選と、決勝1半荘目・順位決定戦のポイントの合計。同じ合計は同じ順位の数字。参考の順位。決勝が2半荘以上の会だけ）。一番下の「半荘ごとの組み合わせ」は「卓ごとの結果」にする（点数入力ページの「卓ごとの結果」と同じ中身＝入った卓ごとに名前・点棒・順位・ポイント。たたんで出し、名前を選んだ人は自分の名前に色。2026-11-14 主催）。順位決定戦の卓は、順位は卓の中の順（同じ点棒は予選の順位が上の方）のままで、ポイントはふつうの卓と同じ計算で出す（トータルの順位に足す分。点数入力ページの「卓ごとの結果」も同じ。2026-11-14 主催「ポイントが入っていない」）。最終順位の決め方とルールのページの「ポイントはつけません」は変えない。
  - 受け口を読めないとき（2026-11-14 主催「元に戻ってる」）: トップ・点数入力・対戦表・幹部用は、開いたときの受け口を `getApi` で読む（読めなかったら2秒・4秒待って、あと2回まで。1回は15秒で打ち切る）。結果を見た端末は、回の名前だけを `halukai:end:<会>` に覚え、受け口を読む前と読めなかったときも結果の後の形で出す（トップの結果の欄は「結果を読み込んでいます…」か「結果を読めませんでした（通信）」と「もう一度読む」）。受け口を読めたら、結果が出ていなければ覚えを消す。
  - 結果の前の形を一瞬出さない（2026-11-14 主催「下のページが一瞬表示される」）: 開催日から後に、結果を覚えていない端末で開いたときは、トップと点数入力は受け口の返事を待ってから本文を出す（待つ間は「読み込み中…」のままで、ルールと早見表のボタンも出さない。4秒たっても返事がなければ待たずに出す）。開催日より前と、結果を覚えた端末と、点数入力の `?unei=1` は待たない。
  - 「最新に更新」のボタンと、点数の最終更新の時刻は、自分の席の欄に1つだけ置く。
  - 本文は受け口を待たずに出す（開催日から後で結果を覚えていない端末は待つ。上の「結果の前の形を一瞬出さない」）。名前は、受け口が返るまで番号のまま。打ち上げの欄は「回答を読み込み中…」と出す。
  - 決勝のある会は、自分の席の下に「K位ライン（決勝に行ける目安）」を出す。名前を選ぶと、いまの予選の順位・ラインまでの差・次の半荘で要る点棒の目安が出る（2026-11-03 に点数入力ページから移した。主催）。表は順位と必要な点棒だけ（次の半荘で要るポイントは、どの順位でも同じため）。
  - 開催日（`date`）は、画面に出ているときだけ2分ごとに受け口を読み直す。打ち上げの欄で選んで、まだ送っていない印は戻さない。
  - 開催日は、日時と場所を「当日の流れ」の見出しの下へ移す。ほかの日は一番上に置く。
  - 打ち上げの欄は、まだ答えていない間だけ開く。答えた後はたたみ、見出しに「回答済み: 〇〇」と出す。
  - 全部の卓の組み合わせは、名前を選んだ人にはたたんで出す（自分の席の表があるため）。
  - たたむ欄は、名前や回答が変わったときだけ開け閉めする。人が開け閉めした欄は、読み直しで戻さない。
- 点数入力: 卓の欄は、トップで選んだ自分の卓を先に選ぶ。人が選び直したら、その半荘の間は動かさない。
  - 選んだ卓に点数があれば、緑の帯で「入力済み」と出す。狭い画面では、半荘と卓の欄を縦に並べる。
  - 点棒は、人数−1人を打つと残りの1人が自動で入る。入力済みの卓を直すときも、打ち直した欄が人数−1になれば、元の点棒のままの欄が自動になる（2026-11-14）。1人を空けても自動。打っている最中の欄は埋めない。
  - 「ポイントの計算」はたたんで出す。順位点が同じ人数の行はまとめる（0人と1人が同じなら「0〜1人」）。
  - 集計表は「順位・プレイヤー・合計pt・K位ライン・半荘ごと・半荘数」の順。名前の列は、横に動かしても左に残る。
  - 自分の行に色をつける。決勝に進む人と優勝は太字だけ。赤は、マイナスと決勝ラインの線だけに使う。
  - 集計表の説明は「表の見方」にたたむ。決勝のある会は、表の上に赤い線の意味だけを1文で出す。
  - 「決勝の卓」は、予選が終わるまではたたむ（開くと、いまの順位での暫定）。「最終順位」は、予選が終わるか決勝の点数が入るまで出さない。
  - 予選が終わっても、決勝に進む人や順位決定戦の卓の境目が決まらない同点の間は、「決勝の卓」の見出しを「予選の合計が同点で、まだ決まりません」にする（前は「予選の順位で決まりました」と出て、中の【注意】と食い違っていた。2026-11-04）。
- 対戦表: 2〜8章（くじの説明）は、抽せんの前も後も最初からたたむ（2026-11-04）。URL に `#` がなく、決勝最終実況の最中なら9章へ移る。
  - 1章の半荘ごとの組み合わせは、たたんで出す（トップと同じ表のため）。抜け番の表は出したまま（抜け番もお休みもない回は出さない）。
  - 名前が届く前は、表の上に「名前を読み込み中」と出す（そのあいだ表は番号）。名前が届いて出し直すときも、人が開けた表は開いたままにする（2026-11-14。前はたたまれ、先に開いた人には番号しか見えなかった）。
  - 上の「決勝ライン」のボタンは、トップの K位ラインの欄へ飛ぶ（2026-11-03 に目安をトップへ移したため）。トップにその欄が出る会だけ出す。
  - 9章の「運営の入力」は、幹部用ページの「実況を入れる」から開いたとき（URL に `?unei=1`）だけ出す。参加者の画面には出さない（2026-11-03。主催）。
- 幹部用: 生年月日の欄は、出席確認の「生年月日の欄を出す」を押したときだけ出す（受付のチェックの邪魔にしない）。
  - 決勝最終実況の会（`jikkyo`）は、時間割の下に「決勝最終実況」の欄を出す。「実況を入れる」で、対戦表の9章を運営の入力つきで開く。
  - 時間割は打ち上げの下へ移し、たたむ。見出しに、いまの行を出す。
  - 準備と出席確認のチェックは端末ごと。その注意は、出席確認の下に1つだけ置く。
- ルール: 1章（早見表）のほかの章はたたむ（スマホで36画面あったため）。目次・URL の `#`・質問の「ルールのこの場所へ」で移るときは、その章を開く。

## ホーム画面のアプリ（PWA）

- 会ごとに `g/<会>/manifest.json` とアイコン（`icon-512.png`・`icon-192.png`・`icon-180.png`）を持つ。`python kai/tools/make_pwa.py` が `taikai.json` の `short`・`group`・`color`・`pai` から作る（`short`・`color`・`pai` を変えたら作り直す）。
- ページは `?g=` から会の manifest を選ぶ。ホーム画面から開くと、その会のトップページが開く。
- 読み込みの手伝い（`sw.js`）は、ページの見た目（HTML・アイコン・manifest）だけを手元に置く。設定・組み合わせ（`.json`）と受け口は手元に置かず、いつも新しく読む。`sw.js` の中身を変えたら `CACHE` の番号を上げる。
- 古いページを出さない（2026-11-14 主催）: GitHub Pages はページを端末に10分まで置く（`max-age=600`）。各ページは `<head>` で `fresh.js` を読み、開いたときと裏から戻ったときに、出ているページの日時（`document.lastModified`）とサーバーの日時（HEAD）を比べる。新しい版があれば取り直して開き直す。そのページで何か入れた後は、一番上に「新しい版があります」の知らせだけ出す。同じ版への自動の開き直しはタブごとに1回。ページを足したら、`<head>` に `fresh.js` を読む行を足す。
- LINE で配るときは、URL に `openExternalBrowser=1` を付ける（LINE の中のブラウザでなく、Safari や Chrome で開く＝ホーム画面に追加できる）。貼る文は `docs/LINE案内文.md`（リポ直下の docs）。

## 回ごとに

- 書き換えるのは、その会の `taikai.json`（大会設定）と `kumiawase.json`（組み合わせ。`tools/kumiawase.py` と `tools/kuji.py` が書く）。くじの会は `kata.json`（型。`tools/kumiawase.py` が書く）も。ページは触らない。
- ページはこれらのファイルを毎回読み直す（キャッシュしない）。push してから1〜2分で全員の画面に出る。
- 名前はファイルに置かない。受け口の名簿（回ごと）にだけ持ち、ページが読んで出す。番号は回ごとに P1 から振る。
- 受け口の作り方は `gas/README.md`。前日・当日・終わった後の手順は `docs/普段の回_手順書.md`（リポ直下の docs）。
- 道具: 組み合わせを作る `tools/kumiawase.py`・くじで組み合わせを決める `tools/kuji.py`・名簿を送る／受け口を試す `tools/meibo.py`・結果を保管庫に残す形で出す `tools/kekka.py`。

順位点の書き方:

- 固定（4麻の初期値。第20回と同じ）: `"uma": [30, 10, -10, -30]`。25,000持ち・30,000返しなら、オカ20を足して1位は+50。
- 返し以上の人数で変わる（3麻の決めごと。Halu杯は 2026-11-10 まで、35,000持ち・40,000返しでこれ）: `"uma": {"0": [30,-10,-20], "1": [30,-10,-20], "2": [20,0,-20]}`。返しちょうども「以上」に数える。表にない人数は `"1"` を使う。
- Halu杯（2026-11-10 から）: 45,000持ち・50,000返し・`"uma": [15, 0, -15]`。オカ15を足して、1位+30・2位0・3位−15（持ち点から見れば +25・−5・−20）。

計算のきまり:

- ポイント＝（点棒−返し）÷1,000＋順位点。1位にはオカ（返し−持ち点）×人数÷1,000を足す。丸めない（100点＝0.1ポイント）。
- 同点の順位点は分ける。0.1で割り切れない分は起家に近い方が多く取る。
- 予選の順位は合計ポイント。抜け番の半荘は0ポイント。
- 決勝に出るのは予選の上位（卓数×人数）。予選の最後の半荘で「お休み」（途中で抜けた）の人は飛ばして、下の人を繰り上げる。2卓以上は予選の順位で蛇行に分ける（2卓なら 1・4・5・8位／2・3・6・7位）。決勝を何半荘打っても卓の顔ぶれは同じ。
- 決勝ライン（決勝のある会。第20回の6位ラインと同じ考え方）: 点数入力ページの集計表に「K位ライン」の列と赤い線を出す（K＝決勝の卓数×人数）。
  - ラインは、自分を除いた人の合計の上から K 番目。途中で抜けた人と、まだ打っていない人は数えない。
  - 「あと +N」は上回るのに要るポイント（同点は年齢や平均順位で決まるため、ラインより0.1多く）。「圏内 (+N)」は K+1位との差。ラインと同じ合計は「圏内（年齢）」「圏内（平均順位）」「圏内（3着率）」「圏内（同点）」「同点（年齢で決まる）」「同点（集計係が決める）」と出す（`doten` の会は「同点（年齢で決まる）」を出さない）。
  - トップで自分の名前を選ぶと、トップの「K位ライン（決勝に行ける目安）」に、ラインまでの差と、次の半荘の順位ごとに要る点棒の目安が出る（2026-11-03 に点数入力ページから移した）。順位点が返し以上の人数で変わる会（3麻）は、少ない方の順位点で計算する（目安を甘くしない）。
  - トップの計算（`umaFor`・`calcTable`・`prelimStats`・`borderFor`・`lineTie`）は点数入力ページと同じ。どちらかを直したら、もう片方も直す。
  - 全部の半荘が確定したら、列・線・欄とも出さない。
- 決勝に出た人を上に並べ、その下に予選の順で並べる。決勝が1半荘なら素点、複数なら決勝のポイント合計で比べる。卓をまたいで一緒に比べる。
- 決勝の同点は予選の順位が上の方を上にする。1半荘の同じ卓の中は起家に近い方を上にする。
- 予選の合計の同点は、同じ順位の数字で「同点」と出す。`nenrei` の会は、同点の人全員の生年月日が入ると年上から並べる（「年齢」と出す。同じ日なら同点のまま）。生年月日は受け口だけに置き、返すのは年上からの順（agerank）だけ。
- `doten` が `"heikin"` の会は、予選の平均順位が小さい人から並べる（「平均順位」と出す）。それも同じなら `mode` 着の率が低い人から（「3着率」と出す。4麻なら「4着率」）。それも同じなら「同点」。まだ打っていない人は、打った人より下。
  - 半荘の中で同じ点棒で並んだ人は、並んだ順位の幅の真ん中に数える（1位と2位で並べば2人とも1.5位）。最下位で並んだ人は、最下位を並んだ人数で割る（2人なら0.5回ずつ）。
  - 計算は整数で持つ（順位は12倍＝(上の順位＋下の順位)×6、最下位は 12÷並んだ人数）。比べるときは割らずに掛け合わせる（平均の a/n と b/m は a×m と b×n で比べる）。点数入力ページ・トップ・対戦表・`tools/kekka.py` は同じ計算。どれかを直したら、ほかも直す。
- 順位決定戦（`final.junni` が 1）: 決勝に出ない人を予選の順に、上から mode 人ずつの卓に分ける。余りは下の卓から1人ずつ足す（3麻だけ。4人で3人麻雀を回す。7人なら3人卓と4人卓）。足しきれない余りは抜け番。点数は決勝1半荘目（`F1`）の、決勝の卓の後ろの番号の卓に入れる。ポイントはつけず、卓ごとに素点の多い順で最終順位を決める（卓をまたいで入れ替わらない。同じ素点は予選の順位が上の方）。最終順位は、決勝 → 順位決定戦の卓の順 → 残りの人（予選の順）。

## 組み合わせの作り方（tools/kumiawase.py）

```
python kai/tools/kumiawase.py                          … 作って成績を出すだけ（書かない）
python kai/tools/kumiawase.py --write                  … 前日: kumiawase.json に書く
python kai/tools/kumiawase.py --from 3 --absent P5 --write   … 当日: 3半荘目から組み直す（P5 が抜けた）
python kai/tools/kumiawase.py --check                  … いまの kumiawase.json を検査して成績を出す
```

- どれも Halu杯（`g/halu/`）を読み書きする。早川研は `--group hayakawa` を足す。

- 作るときに目指すこと: 同じ相手とできるだけ当たらない・抜け番は多く打った人から回す・一人ひとりの風を均等にする・同じ卓に続けて座らない。
- 同じ引数なら何度作っても同じ表になる。別の表にしたいときは `--seed 2` などを足す。
- 組み直し（`--from N`）は、1〜N−1半荘目をそのまま残し、そこまでの当たり方・風・抜け番を引き継いで N 半荘目から作る。
  - 抜けた人は `--absent` に書く。その人はそれ以降の半荘で「お休み」になる（0ポイント）。
  - 増えた人は、先に `taikai.json` の `players` を増やす。増えた人は打った数が少ないので、抜け番にはなりにくい。
- 成績の見方: 「余分に当たった回数」が「下限」と同じなら、それ以上は減らせない。人数と半荘数によっては、下限が0でも少し残る（例: 4麻13人4半荘は12組。探す回数を増やしても減らなかった）。
- 1回あたり2〜4秒。push してから1〜2分で、トップページと点数入力ページに出る。

## くじ（taikai.json に kuji がある会。tools/kuji.py・kai/kuji/）

抽せんの日のナンバーズ4の当せん番号で、誰がどの枠に入るか（＝卓と抜け番）を決める。第20回のくじと同じ仕組み。

```
python kai/tools/kumiawase.py --write        … 抽せんの前: kata.json（型）と、表が空の kumiawase.json を書く
python kai/tools/kumiawase.py --absent P5 --write
                                             … 抽せんの前: 来られなくなった P5 をくじから外して、型を作り直す
python kai/tools/kuji.py 0482                … 抽せんの後: 計算して表示だけ（書かない）
python kai/tools/kuji.py 0482 --write        … 抽せんの後: kumiawase.json に書く
python kai/tools/kuji.py --check             … kumiawase.json が型と本番の番号のとおりか確かめる
```

- 型は、P1〜PN を枠1〜枠N と読み替えて、ふつうの組み合わせと同じ作り方で作る。抽せんの前に push して公開・固定する（くじのページに作った日時が出る）。
- 抽せんの日の18:00から後は、`--write` が型を書かない（当せん番号が分かった後に型を選べないように。`kumiawase.py` の `KUJI_CUT`）。抽せんを延ばすときは、`kuji` を次の抽せんの日にしてから作る。
- 種＝`<kai>|<抽せんの日>|N4=<当せん番号>`。くじ値＝SHA-256（種＋`|P`＋番号）の16進64桁。くじ値の小さい順に枠1〜（同じなら番号の順）。当せん番号は全角を半角にし、先頭の0も残して4桁。
- 抽せんの前に来られなくなった人は、`--absent` でくじから外して型を作り直す（`--from` は使わない）。
  - 外した人は、くじを引く人の後ろの枠に入り、どの半荘もお休み。型の `out` に残り、くじのページにも出る。
  - 名簿の番号は詰めない（打ち上げの回答と生年月日が P番号ごとに付いているため）。
  - 戻れるようになったら、抽せんの前なら `--absent` から消して作り直す。
- 抽せんの後の組み直し（`--from`・`--absent`・増えた人）は、枠の並びに戻して作り、P番号に戻す（くじで決まった枠と No. の組を保つ）。
  - 種は型と同じ。人が変わらなければ、型のとおりの表に戻る。`--seed` は使えない（抽せんの後に表を選べないように）。
  - `players` は減らせない（来られない人は `--absent`）。型より後に増えた人は、枠を番号のままにして入れる。
  - 型で外した人は、抽せんの後もお休みのまま（`--absent` に書かなくてよい）。当日に来たら `--back P5`（外したときの枠で入る）。
  - 表が変わると `kumiawase.json` に `remade: true` が付き、トップページに「組み直しました」と出る。
- `kuji.py --write` は、ほかの番号では書き直さない（引き直しはしない）。組み直した後も書き直さない。打ち間違いを直すときだけ `--redo`（組み直した表も消える）。
- 当せん番号の確かめ先は、宝くじ公式サイトの当せん番号案内（https://www.takarakuji-official.jp/check/）。
- くじのページ（`kai/kuji/`）は、結果（本番の番号・型どおりか・半荘ごとの卓の表・一人ずつの抜け番。抽せんの後に出る）・決まるまでの流れ・公平にするための決まり・検算・型・出席者一覧・計算のしかた・くじ値と枠・決勝最終実況（`jikkyo` の会だけ）を出す。2〜8章は最初からたたんで出す（開けば読めて、検算もできる）。トップページの「半荘ごとの組み合わせ」にリンクが出る。各ページの切り替えボタンでは「対戦表」と呼ぶ（ページの見出しも「対戦表」）。
- ページの上に、移動のボタン「組み合わせ」（1章）・「決勝ライン」（トップの K位ラインの欄。トップにその欄が出る会だけ）・「決勝最終実況」（9章。`jikkyo` の会だけ）を置く（2026-11-02。決勝ラインの飛び先は、2026-11-03 に点数入力ページの集計から変えた）。トップは、読み込みの後に URL の `#` の場所（K位ラインは `#lineh`）へ移る（受け口の返事の後も、その間に画面を動かしていなければ、もう一度）。点数入力ページも、9章のリンク（最終順位は `#finh`）で1回だけ移る。
- ページの計算は `kumiawase.py` の `kuji_seed`・`draw`・`kata_present`・`out_slots`・`KUJI_CUT` と同じ（SHA-256 はページの中で計算する。第20回と同じ）。どちらかを直したら、もう片方も直す。

## kata.json（くじの型）

```json
{
  "kai": "halu-2026-11-14",
  "made": "2026-11-12 21:00",
  "date": "2026-11-13",
  "players": 10,
  "out": ["P5"],
  "rounds": {
    "1": { "tables": [ { "no": 1, "w": [5, 1, 2] } ], "rest": [] }
  }
}
```

- `w` は枠の番号（席の順。`kumiawase.json` の `p` の代わり）、`rest` は抜け番の枠。
- `date` は抽せんの日（`taikai.json` の `kuji` と同じでないと使わない）、`players` は名簿の人数（P1〜P この数）。
- `out` は抽せんの前に外した人（くじに入らない）。いないときは書かない。くじを引くのは、P1〜P`players` から `out` を除いた人。
- 外した人の枠は後ろの番号（例は10人から P5 を外したので、枠10）。型の中では、どの半荘でもこの枠を使わない。
- `--seed` で作ったときは `seed` も残す。

## kumiawase.json（組み合わせ）

```json
{
  "kai": "halu-2026-11-14",
  "made": "2026-11-13 21:00",
  "from": 1,
  "rounds": {
    "1": { "tables": [ { "no": 1, "p": ["P3", "P7", "P1"] } ], "rest": ["P13"] },
    "3": { "tables": [ … ], "rest": [], "out": ["P5"] }
  }
}
```

- `rounds` のキーは予選の半荘の番号。`p` は席の順（東・南・西・北。東が起家。`bakime` が `true` の会では、同じ卓の顔ぶれだけ）、`rest` はその半荘の抜け番、`out` は途中で抜けた人。
- `made` は作った時刻、`from` はどの半荘から作ったか。2以上なら、トップページに「N半荘目から組み直しました」と出る。
- くじの会は `kuji`（抽せんの日と当せん番号。`kuji.py` が書く）が付く。抽せんの後に組み直すと `remade: true` も付く。抽せんの前は `rounds` が空。
- `kai` が `taikai.json` と違うときは、ページはこのファイルを使わない（前の回の表の取り違えを防ぐ）。
- 決勝と順位決定戦の卓は載せない。どちらも予選の順位から決まり、席は自動卓のサイコロで決める（`bakime` が `true` の会は牌を引いて決める）。
