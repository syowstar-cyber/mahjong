# Haluリーグの受け口の配置手順（Google Apps Script）

Halu杯の受け口（`kai/gas/` と、halu-cup リポの `gas/`）とは**別のプロジェクト**として作る。
データを混ぜないため。
ブラウザで人が行う（Claude は代行しない）。所要5分。ドライブの権限は求められない。

**一度デプロイすれば、シーズンが替わってもデプロイし直さない。**
URL は変わらない。シーズンごとの置き場は、シーズンの名前で分かれる。

## 1. スクリプトを作る

1. https://script.google.com を開き、「新しいプロジェクト」。
2. `コード.gs` の中身を全部消し、この階層の `Code.gs` を貼り付けて保存（Ctrl+S）。
3. プロジェクト名を「halu-league」など分かる名前にする。

## 2. ウェブアプリとして公開する

1. 右上「デプロイ」→「新しいデプロイ」→ 種類の歯車で「ウェブアプリ」。
2. 「次のユーザーとして実行」＝**自分**、「アクセスできるユーザー」＝**全員**。
3. 「デプロイ」→ 権限の確認が出たら自分のアカウントで許可する。
4. 表示された**ウェブアプリの URL**（`https://script.google.com/macros/s/.../exec`）をコピーする。
5. URL を Claude に渡す。

2026-11-08 にデプロイ済み。URL は `league/s/season1/season.json` の `api` にある。
新しいシーズンの season.json には、同じ URL を写す。

## 3. URL を受け取った後（Claude が行う）

1. `league/s/<シーズン>/season.json` の `api` に URL を入れる。
2. `python league/tools/meibo.py --test` で試しの送信をする。シーズン `setup-test` を使い、最後に空へ戻す。
3. `python league/tools/meibo.py <名簿ファイル>` で、名簿（P番号と名前）を送る。
4. 3枚のページを本物の受け口につなぎ、通して試す（点数入力・調整表・スコアボード）。
5. 試しに入れた点数と予定の印は、ページから消す。点数は「取り消し」、印はもう一度押して送る。

- 名簿の正典は保管庫の `60_暮らし\Haluリーグ_参加者名簿.md`。
- そこから1行1人「P1 呼び名」のファイルを scratchpad に作って渡す。リポには置かない。
- 番号を入れ替えたときは、名簿を送り直す。空いた番号は `--drop P9` のように消す。
- 名簿は日本語を含む。Git Bash の `curl -d` で送ると、文字コードが崩れる。meibo.py は urllib（UTF-8）で送る。
- `--test` の後も、送信履歴（`LOG`）と、`setup-test` の最終更新の1項目は残る。

## エディタで動かす関数（人が行う）

| 関数 | すること |
|---|---|
| `listSeasons` | 置いてあるシーズンの一覧（点数の卓数・名簿の人数・予定を付けた人数・最終更新）と、保存領域の使用量を「実行ログ」に出す |
| `purgeSeason` | 1つのシーズンを消す（点数・名簿・予定・最終更新）。`purgeSeason` のすぐ上の `const PURGE = '';` にシーズンの名前を入れて保存し、実行する。終わったら `''` に戻す |
| `resetAll` | 全部（すべてのシーズンと送信履歴）を消す |

## 気をつけること

- 保存領域は全体で500KBまで。1シーズンは30KBほど（点数120卓で15KB、予定の印で15KB）。
- 目安で10シーズンは置ける。`listSeasons` で量を見て、古いシーズンから `purgeSeason` で消す。
- `Code.gs` を直したときは「デプロイを管理」→ 編集（鉛筆）→ バージョン「新しいバージョン」→ デプロイ。
- このやり方なら URL は変わらない。`season.json` も直さなくてよい。
- 受け口にキーはない（Halu杯と同じ）。値の範囲だけを検査し、送信の時刻を送信履歴（`LOG`・直近100件）に残す。
