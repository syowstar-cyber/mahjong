# 普段の回の手順書 — 普段の回（3麻・4麻）を、会ごとに前日・当日・終わった後の順に回す

正典（先に読む。ここへ写さない）:
- 会の一覧・設定・組み合わせ・計算の決まり＝`mahjong/kai/README.md`
- 決めごと（進め方・3麻の順位点・抜け番・決勝・当日の頼み方・結果の記録）＝`mahjong/docs/普段の回_設計.md`

会は `<会>` と書く（Halu杯＝`halu`・早川麻雀研究会＝`hayakawa`）。設定はその会の `mahjong/kai/g/<会>/taikai.json`。
コマンドはワークスペース根（`tools/mdio.py` と `.claude` がある所）で、書いてあるとおりに打つ。`--group <会>` は必ず付ける。ほかのフラグは足さない。
報告は段ごとに `done`／`failed`／`skipped` の1行。指摘が無い段は「異常なし」と書く。

## 越えない線

- 名前・連絡先・金額を mahjong のファイルに書かない。名前を置くのは受け口と保管庫だけ。名簿のファイルは scratchpad に置く。
- push は、主催がその回に頼んだときだけ（mahjong は公開リポ）。
- 受け口の名前は消さない（2026-10-25 主催）。
- `Code.gs` のデプロイは人が行う。Claude は代行しない（受け口は1つをどの会でも使う。デプロイは 2026-10-25 に済み）。
- 3麻の持ち点と返しは、毎回主催に聞く（初期値なし）。
- `kai` は `<会>-YYYY-MM-DD`。ほかの会の回の名前と重ねない。
- `--absent` には、その回に抜けた人を**全員**書く（前の組み直しで書いた人も外さない）。

## A. 新しい会を足すときだけ

1. `mahjong/kai/g/<会>/taikai.json` と `kumiawase.json` を、既存の会の見本から複製して作る（`kai`＝`<会>-mihon`・`group`＝会の名前・`short`・`color`・`pai`＝主催に聞く・`api` は同じ URL）。
2. `python mahjong/kai/tools/kumiawase.py --group <会> --check --quiet` → `■ 形は問題なし` なら done。
3. `python mahjong/kai/tools/make_pwa.py <会>` → `OK <会>:` で始まる1行なら done（ホーム画面のアプリの manifest とアイコン）。アイコンの絵を Read で開いて確かめる。
4. `mahjong/kai/README.md` の「会」の表と、`mahjong/docs/LINE案内文.md` に1つずつ足す。commit。push は主催が頼んだときだけ。

## B. 前日

1. 主催に聞く（チャット）: 会／開催日／3麻か4麻か／出席者の呼び名（P1から順に）／予選の半荘数／決勝の卓数と半荘数（なしも可）／3麻なら持ち点と返し、順位点が表の初期値のままか／卓番号（店の卓札）。決まらない項目があれば止めて聞き直す。
2. `mahjong/kai/g/<会>/taikai.json` を書き換える。`kai`＝`<会>-YYYY-MM-DD`、`date`＝開催日、`title`、`mode`、`players`＝出席者の数、`prelim`、`final`、`start`、`return`、`uma`、`tables`、`locked`＝`[]`。`group` と `api` は触らない。
3. 名簿を scratchpad の `meibo.txt` に Write する（UTF-8・1行1人「P1 呼び名」）。
   `python mahjong/kai/tools/meibo.py --group <会> <scratchpad>/meibo.txt` → `OK roster 送った N人` の N が出席者の数と同じなら done。`NG` は表示どおり直して1回だけ打ち直す。
4. `python mahjong/kai/tools/kumiawase.py --group <会> --write` → 最後の行が `書きました:` なら done。成績の「余分に当たった回数」と「下限」を報告に入れる。
5. `python mahjong/kai/tools/kumiawase.py --group <会> --check --quiet` → `■ 形は問題なし` なら done。
6. `mahjong` で commit。主催が頼めば push する。push の1〜2分後に `https://syowstar-cyber.github.io/mahjong/kai/?g=<会>` を内蔵ブラウザで開き、`get_page_text` で題名・半荘ごとの表・名前が出ていることを確かめる。
7. 主催へ伝える: LINE に貼る文は `mahjong/docs/LINE案内文.md` のその会の節（URL に `openExternalBrowser=1` 付き。毎回同じ。貼るのは主催。固定のアナウンスに置いてあれば、貼り直さなくてよい）。

## C. 当日（会場からは、スマホの Remote Control で家のPCに頼まれる）

1. 始まる前に欠席が出た: `python mahjong/kai/tools/kumiawase.py --group <会> --from 1 --absent P5 --write`（P5 を欠席者に置き換える。複数はカンマ区切り）→ `書きました:` → B6 と同じく commit・push・表示の確認。
2. 途中で抜けた: N半荘目から組み直す。`python mahjong/kai/tools/kumiawase.py --group <会> --from N --absent P5 --write`（`--absent` には抜けた人を全員）→ B6。
3. 途中で増えた: `taikai.json` の `players` を増やす → 増えた人の行だけを scratchpad に Write して `meibo.py --group <会>` で送る（`OK roster`）→ 2 と同じく `--from N` で組み直す → B6。
4. 確定: 主催が「N半荘目を確定」と言ったら、`locked` に `"N"`（決勝は `"F1"` など）を足して commit・push。
5. 決勝の境目が同点（点数ページに【注意】）: 集計係が決める。Claude は決めない。
6. 点数ページで「混み合っています」: 少し待って送り直すよう伝える。
7. 家のPCが落ちて頼めない: ※案（未確認）最初の表のまま進め、抜けた人の席はその場で決める。

## D. 終わった後

1. 主催が頼めば、`locked` に全部の半荘を入れて commit・push する（報告の欄が消え、順位だけになる）。
2. `python mahjong/kai/tools/kekka.py --group <会> > <scratchpad>/kekka.md` → 先頭が `# <会の名前（group）> <開催日>` で、「点数がそろっていない半荘: なし。」なら done。そろっていなければ主催に確かめる。
3. `python tools/mdio.py write "Obsidian/60_暮らし/麻雀/<会の名前（group）>_<開催日>.md" "<scratchpad>/kekka.md"` → `OK W` なら done。`MDERR` は成功扱いにせず、理由（パス・権限・ロック）を直して1回だけ打ち直す。
4. 最終順位の上位を主催へ報告する（チャットでは名前を出してよい。リポには書かない）。
5. 名前は消さない。受け口の保存領域（全体で500KB）は、人がエディタで `listKai` を見て、多くなったら古い回から `purgeKai` で消す（`mahjong/kai/gas/README.md`）。

## この手順固有の禁止事項

- 組み合わせを手で書き換えない。必ず `kumiawase.py` を通す。
- 点数を Claude が受け口へ送らない（送るのは卓の代表と集計係）。`meibo.py --test` が送るのは回 `setup-test` だけ。
- 保管庫の結果を手で書き換えない。直すときは受け口の点数を直してから `kekka.py` で出し直す。
- 決勝の境目・同点を Claude が決めない。
- ほかの会の `g/<会>/` を、その会の回のために書き換えない。
