# 普段の回の手順書 — 普段の回（3麻・4麻）を、会ごとに前日・当日・終わった後の順に回す

正典（先に読む。ここへ写さない）:
- 会の一覧・設定・組み合わせ・計算の決まり＝`mahjong/kai/README.md`
- 決めごと（進め方・3麻の順位点・抜け番・決勝・当日の頼み方・結果の記録）＝`mahjong/docs/普段の回_設計.md`

会は `<会>` と書く（Halu杯＝`halu`・早川麻雀研究会＝`hayakawa`）。設定はその会の `mahjong/kai/g/<会>/taikai.json`。
コマンドはワークスペース根（`tools/mdio.py` と `.claude` がある所）で、書いてあるとおりに打つ。`--group <会>` は必ず付ける。ほかのフラグは足さない。
報告は段ごとに `done`／`failed`／`skipped` の1行。指摘が無い段は「異常なし」と書く。

## 越えない線

- 名前・連絡先・金額を mahjong のファイルに書かない。名前を置くのは受け口と保管庫だけ。名簿のファイルは scratchpad に置く。
- push は、主催がその回に頼んだときだけ（mahjong は公開リポ）。
- 受け口の名前は消さない（2026-10-25 主催）。
- `Code.gs` のデプロイは人が行う。Claude は代行しない（受け口は1つをどの会でも使う。デプロイは 2026-10-25 に済み。当日の操作に対応した版は 2026-11-15 に済み）。
- 3麻の持ち点と返しは、毎回主催に聞く（初期値なし）。
- `kai` は `<会>-YYYY-MM-DD`。ほかの会の回の名前と重ねない。
- `--absent` には、その回に抜けた人を**全員**書く（前の組み直しで書いた人も外さない。くじの型で外した人は書かなくてよい）。
- くじは引き直さない。`kuji.py --redo` は、打ち間違えた番号を公式の番号に直すときだけ、主催に確かめてから使う。

## A. 新しい会を足すときだけ

1. `mahjong/kai/g/<会>/taikai.json` と `kumiawase.json` を、既存の会の見本から複製して作る（`kai`＝`<会>-mihon`・`group`＝会の名前・`short`・`color`・`pai`＝主催に聞く・`api` は同じ URL）。
2. `python mahjong/kai/tools/kumiawase.py --group <会> --check --quiet` → `■ 形は問題なし` なら done。
3. `python mahjong/kai/tools/make_pwa.py <会>` → `OK <会>:` で始まる1行なら done（ホーム画面のアプリの manifest とアイコン）。アイコンの絵を Read で開いて確かめる。
4. `mahjong/kai/README.md` の「会」の表と、`mahjong/docs/LINE案内文.md` に1つずつ足す。commit。push は主催が頼んだときだけ。

## B. 前日

1. 主催に聞く（チャット）: 会／開催日／3麻か4麻か／出席者の呼び名（P1から順に）／予選の半荘数／決勝の卓数と半荘数（なしも可）／3麻なら持ち点と返し、順位点が表の初期値のままか／卓番号（店の卓札）／組み合わせをくじで決めるか（決めるなら抽せんの日＝月〜金）／決勝最終実況を出すか（3麻・決勝1卓・2半荘以上でくじの回だけ）／打ち上げの出欠を取るか／幹部の準備の項目／当日の操作（くじの番号・時刻ずらし・確定）を幹部用ページで行うか。決まらない項目があれば止めて聞き直す。
2. `mahjong/kai/g/<会>/taikai.json` を書き換える。`kai`＝`<会>-YYYY-MM-DD`、`date`＝開催日、`title`、`mode`、`players`＝出席者の数、`prelim`、`final`、`start`、`return`、`uma`、`tables`、`locked`＝`[]`、`kuji`＝抽せんの日（くじで決める回だけ。決めない回は消す）、`jikkyo`＝`true`（決勝最終実況を出す回だけ）、`uchiage`＝`true`（出欠を取る回だけ）、`junbi`＝準備の項目の並び、`tojitsu`＝`true`（当日の操作を幹部用ページで行う回だけ）。`group` と `api` は触らない。
3. 名簿を scratchpad の `meibo.txt` に Write する（UTF-8・1行1人「P1 呼び名」）。
   `python mahjong/kai/tools/meibo.py --group <会> <scratchpad>/meibo.txt` → `OK roster 送った N人` の N が出席者の数と同じなら done。`NG` は表示どおり直して1回だけ打ち直す。
   - `jikkyo` の回は続けて `python mahjong/kai/tools/meibo.py --group <会> --test` → 1行目が `OK test` なら done。`NG test 受け口が古い` は、主催に受け口の新しいバージョンのデプロイを頼む（人が行う。`mahjong/kai/gas/README.md`）。
4. `python mahjong/kai/tools/kumiawase.py --group <会> --write` → 最後の行が `書きました:` なら done。成績の「余分に当たった回数」と「下限」を報告に入れる。
   - くじの回は、型（`kata.json`）と表が空の `kumiawase.json` を書く。抽せんの日の18:00を過ぎると書かない（`failed`。抽せんの日を延ばすかを主催に聞く）。
   - くじの回で、抽せんの前に来られなくなった人が出た: `--absent P5` を足して B4〜B6 をやり直す（名簿の番号は詰めない。`players` も減らさない）。
5. `python mahjong/kai/tools/kumiawase.py --group <会> --check --quiet` → `■ 形は問題なし` なら done（くじの回は、続く `■ 型は問題なし` まで見る）。
6. `mahjong` で commit。主催が頼めば push する。push の1〜2分後に `https://syowstar-cyber.github.io/mahjong/kai/?g=<会>` を内蔵ブラウザで開き、`get_page_text` で題名・半荘ごとの表・名前が出ていることを確かめる。
   - くじの回の抽せんの前は、表の代わりに「くじで決まる」の案内が出る。くじのページ `https://syowstar-cyber.github.io/mahjong/kai/kuji/?g=<会>` で、5章に型が出ていることも確かめる。
   - くじの回の型は、抽せんの前に push する（公開して固定する）。push の頼みが無ければ、主催に「抽せんの前に push が要る」と伝える。
   - `tojitsu` の回は、幹部用ページ `https://syowstar-cyber.github.io/mahjong/kai/kanbu/?g=<会>` も開き、`get_page_text` で「当日の操作」の下に「半荘の確定」が出ていれば done（受け口が当日の操作に対応している）。「受け口が古いため」と出ていたら、主催に受け口の新しいバージョンのデプロイを頼む（人が行う。`mahjong/kai/gas/README.md`）。「当日の操作」も無ければ、`taikai.json` の `tojitsu` を見直す。
7. 主催へ伝える: LINE に貼る文は `mahjong/docs/LINE案内文.md` のその会の節（URL に `openExternalBrowser=1` 付き。毎回同じ。貼るのは主催。固定のアナウンスに置いてあれば、貼り直さなくてよい）。

## B'. 抽せんの後（くじの回だけ。抽せんの日の夜）

`tojitsu` の回: 主催か幹部が、抽せんの日の18:00から幹部用ページの「当日の操作」で番号を入れる。Claude は番号を書かない・commit も push もしない。主催が確かめを頼んだときだけ 1〜3 を行う。
`tojitsu` の無い回: 4〜8 を行う。

1. 内蔵ブラウザで `https://www.takarakuji-official.jp/check/` を開き、抽せんの日のナンバーズ4の当せん番号を読む。まだ出ていないときは止めて主催に知らせる（`failed`）。
2. `python mahjong/kai/tools/kuji.py --group <会>` → `受け口の番号を使います: <番号>` の番号が 1 と同じなら done（表示だけで、何も書かない）。
   - 違う: 幹部用ページの「直す」で直すよう主催に伝える（点数が入る前だけ直せる。`failed`）。
   - `受け口にくじの番号がまだない`: まだ入っていないと主催に伝える（`skipped`）。
   - `受け口を読めない`: 通信を確かめて1回だけ打ち直す。
3. くじのページ `https://syowstar-cyber.github.io/mahjong/kai/kuji/?g=<会>` を内蔵ブラウザで開き、`get_page_text` で1章に「本番の番号」と「型と本番の番号のとおり」が出ていることを確かめる。

6. `python mahjong/kai/tools/kuji.py <番号> --group <会> --write` → 最後の行が `書きました:` なら done。拒否されたら（番号がもう入っている・組み直した表がある）止めて主催に知らせる。
7. `python mahjong/kai/tools/kuji.py --group <会> --check` → `一致` で始まる行なら done。`不一致` は止めて主催に知らせる。
8. B6 と同じく commit・push・表示の確認。くじのページの1章に「本番の番号」と「型と本番の番号のとおり」が出ていることも確かめる。

## C. 当日（会場からは、スマホの Remote Control で家のPCに頼まれる）

くじの回の抽せんの後も、C1〜C3 のコマンドは同じ。道具が、くじで決まった枠を保って組み直す。`--seed` は使えない。
くじの型で外した人は、どの半荘もお休みのまま。その人が来たら N半荘目から入れる: `python mahjong/kai/tools/kumiawase.py --group <会> --from N --back P5 --write`（ほかに抜けた人がいれば `--absent` も全員付ける）→ `書きました:` → B6。
`tojitsu` の回: 時刻ずらしと半荘の確定は、主催か幹部が幹部用ページの「当日の操作」で行う（C4 は主催に頼まれたときだけ）。
`tojitsu` の回で `kumiawase.json` に `kuji`（本番の番号）がまだ無いとき（`kumiawase.py` が `kuji.py --write` を案内して止まったときも）は、C1〜C3 と型で外した人を入れる前に `python mahjong/kai/tools/kuji.py --group <会> --write` → 最後の行が `書きました:` なら done（受け口の番号で書く）。`受け口にくじの番号がまだない` は止めて主催に知らせる（`failed`）。

1. 始まる前に欠席が出た: `python mahjong/kai/tools/kumiawase.py --group <会> --from 1 --absent P5 --write`（P5 を欠席者に置き換える。複数はカンマ区切り）→ `書きました:` → B6 と同じく commit・push・表示の確認。
2. 途中で抜けた: N半荘目から組み直す。`python mahjong/kai/tools/kumiawase.py --group <会> --from N --absent P5 --write`（`--absent` には抜けた人を全員）→ B6。
3. 途中で増えた: `taikai.json` の `players` を増やす → 増えた人の行だけを scratchpad に Write して `meibo.py --group <会>` で送る（`OK roster`）→ 2 と同じく `--from N` で組み直す → B6。
4. 確定: 主催が「N半荘目を確定」と言ったら、`locked` に `"N"`（決勝は `"F1"` など）を足して commit・push。`tojitsu` の回で頼まれたときは、大会設定の確定は幹部用ページでは外せない、と報告に添える。
5. 決勝の境目が同点（点数入力ページに【注意】）: 集計係が決める。Claude は決めない。
6. 点数入力ページで「混み合っています」: 少し待って送り直すよう伝える。
7. 家のPCが落ちて頼めない: ※案（未確認）最初の表のまま進め、抜けた人の席はその場で決める。
8. 決勝最終実況（`jikkyo` の回）: 局ごとの点棒は、運営1人が対戦表の9章「運営の入力」で送る。Claude は送らない。運営の画面に「受け口がまだ実況に対応していません」と出たら、主催に受け口の新しいバージョンのデプロイを頼む（人が行う）。

## D. 終わった後

1. `tojitsu` の回で `kumiawase.json` に `kuji`（本番の番号）がまだ無いとき: `python mahjong/kai/tools/kuji.py --group <会> --write` → 最後の行が `書きました:` なら done（表を記録に残す）。commit する（次の回の型を作る前に。push は主催が頼んだときだけ）。番号がもうある回と `tojitsu` の無い回は `skipped`。
2. 主催が頼めば、`locked` に全部の半荘を入れて commit・push する（報告の欄が消え、順位だけになる）。`tojitsu` の回も同じ（幹部用ページの確定だけでは、トップへ移る形と結果の写しにならない）。
3. `python mahjong/kai/tools/kekka.py --group <会> > <scratchpad>/kekka.md` → 先頭が `# <会の名前（group）> <開催日>` で、「点数がそろっていない半荘: なし。」なら done。そろっていなければ主催に確かめる。
4. `python tools/mdio.py write "Obsidian/60_暮らし/麻雀/<会の名前（group）>_<開催日>.md" "<scratchpad>/kekka.md"` → `OK W` なら done。`MDERR` は成功扱いにせず、理由（パス・権限・ロック）を直して1回だけ打ち直す。
5. 最終順位の上位を主催へ報告する（チャットでは名前を出してよい。リポには書かない）。
6. 名前は消さない。受け口の保存領域（全体で500KB）は、人がエディタで `listKai` を見て、多くなったら古い回から `purgeKai` で消す（`mahjong/kai/gas/README.md`）。`halu-2026-11-14`（第5回）は消さない。halu-cup の `sanma5/` とトップの優勝者の名前が、この回の名簿を読んでいる（消すと P番号に戻る）。

## この手順固有の禁止事項

- 組み合わせを手で書き換えない。必ず `kumiawase.py` を通す（くじの結果は `kuji.py`）。`kata.json` も手で書き換えない。
- 抽せんの日を過ぎてから型を作り直すために、`taikai.json` の `kuji` を書き換えない（書き換えるのは、主催が抽せんを延ばすと決めたときだけ）。
- 点数・決勝最終実況・当日の操作（くじの番号・時刻ずらし・確定）を Claude が受け口へ送らない（点数は卓の代表と集計係、実況は運営1人、当日の操作は主催か幹部が幹部用ページで送る）。`meibo.py --test` が送るのは回 `setup-test` だけ。
- 保管庫の結果を手で書き換えない。直すときは受け口の点数を直してから `kekka.py` で出し直す。
- 決勝の境目・同点を Claude が決めない。
- ほかの会の `g/<会>/` を、その会の回のために書き換えない。
